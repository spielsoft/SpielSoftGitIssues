# Approved implementation scope

Use the issue's existing description and discussion as the brief when they state
the current/desired behavior, testable acceptance criteria and scope. Link the
relevant evidence and dependencies. Add only missing information to the approved
batch; no separate brief comment or fixed template is required.

Describe behavior and contracts rather than procedural edit instructions. Cite
product rules and reproduction evidence where they establish the decision.
Pin code references to a revision when useful. State scope exclusions only when
they prevent a plausible misunderstanding. For an existing PR, describe only the
remaining work. Governing project rules and the owner's approved scope control.
